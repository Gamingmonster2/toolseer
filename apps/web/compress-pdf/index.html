Compress PDF

Drop in a PDF and get back a smaller file with an exact before-and-after size report. This build compresses losslessly: every pixel, glyph and vector line is kept, and a file that cannot be shrunk is handed back unchanged. Nothing is ever uploaded.

What compression actually changes

Compressing a PDF is not one operation, it is two, and they cost you different things. Lossless compression rebuilds the file's internal packaging: streams are re-compressed, objects are packed into object streams, the cross-reference table is rewritten, and the leftovers of earlier incremental saves are left out of the new single revision. Nothing on the pages is re-encoded, so every glyph, vector line and image pixel survives unchanged. Balanced and strong are the lossy levels by design: they are meant to resample raster images above a resolution threshold and re-encode them as JPEG, which is where the largest savings come from.

This browser build ships the lossless path only. Choosing balanced or strong today performs the same lossless rebuild as the lossless level, so the three labels describe a design goal for image resampling rather than a difference you will see in your file here and now. The practical consequence is a smaller saving on some documents; the worst case is never a PDF whose images were quietly degraded behind your back.

That difference decides what you should expect. A PDF exported from Word, LibreOffice or a browser print dialog is usually full of slack, and the lossless rebuild can take somewhere between a few percent and a quarter of its size. A PDF that is already just a wrapper around one large JPEG has almost nothing left to squeeze, and the pass may save less than one percent. Once image resampling is available, the lossy levels will help exactly where the weight is: scanned pages and photo-heavy documents.

Text and vector graphics stay sharp

At every level, text stays text. Letters remain selectable, searchable and crisp at any zoom because they were never turned into pixels, and the same is true of vector line art, thin rules and charts. Only raster images would ever be resampled, and only if this build included the lossy path: as it stands, nothing on your pages is re-encoded at any level.

Compression is a one-way door

Lossy compression cannot be undone: once image pixels have been downsampled, the discarded detail is gone, and re-compressing an already compressed file adds another generation of loss instead of recovering anything. That is the trade the lossy levels make by design. Because this build only performs the lossless rebuild, nothing on your pages is degraded today — and keeping your original is still the right habit, so that a later, stronger attempt always starts from the untouched source.

Honest limits of this page

  • It never hands you a bigger file. The page compares the recompressed bytes with your original; if the result is not smaller, it returns the original unchanged and tells you so instead of quietly wasting your time.
  • Metadata removal is real but small. The Remove metadata switch drops the document information fields a PDF carries alongside its pages — title, author, subject, keywords and the software that produced it — which usually saves a few kilobytes and removes the obvious identifying traces. Verify the result if you need certainty, because metadata can also sit in places a switch like this does not reach. It is not redaction: nothing printed on a page changes.
  • The structure is rebuilt. The output is a valid PDF with the same pages, but its internal layout differs from the original. Do not rely on byte-for-byte comparison, and expect a digital signature to be invalidated by the pass, because a signature covers the exact bytes it was created over.
  • Your tab holds the whole file in memory. A few hundred megabytes of scanned pages can exhaust a browser tab. The desktop app runs the same compression on disk instead.

When compression will not get you under the limit

If a scan is already stored as modest-resolution JPEG, no compressor can shrink it without visibly degrading it. The honest options then are to rescan at a lower resolution, split the document into smaller files with Split PDF, or send a link instead of an attachment. Beware of tools that promise sixty percent savings on every file: the only way to reach that on a scan is to throw away resolution your readers may need.

Frequently asked questions

Does compressing a PDF reduce its quality?

Not in this browser build. All three levels currently run the same lossless rebuild, so the file is repacked into tighter internal structures and nothing is re-encoded: images, text and vectors keep exactly their original data. Balanced and strong are designed to resample images above a resolution threshold and re-encode them as JPEG once that step ships, and that kind of loss would be permanent.

Can I get the original quality back after compressing?

There is nothing to restore at the moment, because this build never re-encodes your pages. When image downsampling is available its loss will be permanent, since no operation puts discarded pixels back. Keep the original file and compress a copy of it, and do not re-compress an already compressed file hoping to recover detail.

Which compression level should I choose?

Today the choice changes nothing in the output: lossless, balanced and strong all run the same lossless rebuild, so the safest label is lossless. The levels will start to differ when image resampling ships, and strong will then mean visibly softer images on scans in exchange for a smaller file.

Will the text stay selectable and searchable?

Yes. This tool never rasterises text or vector artwork, at any level, so letters stay selectable, searchable and sharp when zoomed in. Only raster images are resampled, and only at the balanced and strong levels.

What does removing metadata actually do?

It removes the document information fields a PDF carries alongside its pages: title, author, subject, keywords, producer and timestamps. That removes identifying traces and usually saves a few kilobytes. It is not redaction, so any name or number printed visibly on a page is still readable afterwards.

Is my PDF uploaded to a server?

No. The file is read from your disk, recompressed by code running in this browser tab, and handed back to you as a download. Nothing is transmitted anywhere, and the page keeps working with your network disconnected once it has loaded.
