Protect PDF

Encrypt a PDF with a password you choose and decide what readers may print, copy, edit or comment on. The password is used in memory in this tab to derive the key: it is never uploaded, never written to disk and never included in your download.

What a PDF password actually protects

Adding a password uses the standard security handler defined by the PDF specification. The document's streams and strings are encrypted with a key derived from your password, and a reader cannot display the pages until it has derived the same key. With AES-256 that is a genuine cryptographic barrier: without the password the content cannot be decrypted by an ordinary tool, and guessing a long passphrase is not practical.

The permission switches are a different matter, and this is where most tools overclaim. Print, copy, edit and comment are flags inside the encryption dictionary, not cryptography. A well-behaved reader — Acrobat, Preview, most mobile viewers — honours them. A determined person with the right software can ignore them, and anyone who can open the file with the password can usually re-save it without restrictions. Treat the flags as a request, never as a guarantee. If a passage must not be copied, redact it before you send the file, because a flag will not stop a screenshot either.

User password and owner password are different jobs

The user password is what a reader asks for when the file is opened; it is what decrypts the document. The owner password proves authority over the file and is what a reader asks for when someone tries to change the permissions or the passwords. Leave the owner field empty and this tool uses the user password for both roles, which is the simplest choice and leaves the content just as well protected.

Choosing an algorithm

  • AES-256 — the modern default. Supported by Acrobat X and everything newer, and by current browser viewers. Use this unless you have a reason not to.
  • AES-128 — a reasonable fallback when a reader from roughly 2005 to 2010 has to open the file (Acrobat 7 and later). Still a real cipher, with a shorter key.
  • RC4-128 — legacy only. RC4 has known statistical weaknesses and is deprecated; keep it for old software that refuses anything else, and not for sensitive documents.

Defaults on this page, stated plainly

Printing and commenting start switched on; copying text and editing start switched off. That is the shape most people expect from a locked document, and every flag is visible in the settings panel so you can change it before you run the tool. Remember what the flags are worth: the password is the real protection, and the flags are a polite request to honest software.

Practical rules for a password you will not lose

Encryption happens in memory, in this tab. The password is used to derive the key, is never written to storage, never appears in the file name and is never transmitted. We keep no copy of your document and no copy of the password, so there is no recovery path and no reset link if it is forgotten. Keep an unencrypted original somewhere safe, or put the password in a password manager before you send the protected file.

Length beats complexity. A five-word passphrase is harder to guess offline than eight scrambled characters, and whoever holds the file can guess at it without any rate limit. Also be clear about what encryption does not do: it does not stop someone who has the password from sharing the decrypted copy, it does not watermark or expire the document, and it cannot hide information that is printed visibly on a page. If you also want to shrink the file, run it through Compress PDF first and protect the result.

Frequently asked questions

Is my password uploaded or stored anywhere?

No. The password is used in memory in this browser tab to derive the encryption key. It is never sent over the network, never written to local storage or a cookie, and never placed in the output file name or metadata. Because nothing is stored, we also cannot recover it for you.

Can the print and copy restrictions be bypassed?

Often, yes. Permission flags live in the encryption dictionary and well-behaved readers honour them, but they are not cryptography. Anyone who can open the file with the password can usually re-save it without the restrictions. Treat them as a request, and redact anything that must not be copied.

Which encryption algorithm should I choose?

AES-256 unless you must support a very old reader. AES-128 works with Acrobat 7 and later and is still a real cipher with a shorter key. RC4-128 exists only for legacy software and should not be used for sensitive documents, because RC4 has known statistical weaknesses.

What happens if I forget the password?

The document cannot be opened without it. There is no back door, no recovery code and no support route, because we never receive the password or the file. Keep an unencrypted copy of anything you cannot afford to lose, or store the password in a password manager.

What is the difference between the user password and the owner password?

The user password is required to open and decrypt the document. The owner password proves authority to change permissions and passwords. If you leave the owner field empty, this tool uses the user password for both roles.

Is a password-protected PDF safe to email?

The contents are encrypted, so an interceptor cannot read the document without the password. The file itself can still be copied and attacked offline, which is why the password must be long. Send the password through a different channel from the file, for example by message rather than in the same email.
