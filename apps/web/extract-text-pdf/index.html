Extract Text from PDF

Copy the text out of a PDF, page by page, and save it as a plain text file. Documents with a real text layer come out exactly; for scanned pages, turn on OCR and the browser reads them locally with English or Arabic models — no upload, no account.

A text layer is not the same thing as a picture of text

Most PDFs created by Word, Google Docs, LaTeX or a browser print dialog contain a text layer: every character is stored with its font, its position on the page and usually a mapping to a Unicode value. Extracting that layer is a copy operation, not a guess — the characters are already in the file, and the result is as accurate as the document's own mapping. This page reads that layer page by page and hands you plain text you can copy or save as a .txt file.

A scanned PDF is the opposite. A scanner produces one image per page, so the file contains no characters at all, only pixels. Nothing can be extracted because there is no text to extract, which is why this page tells you plainly that a page had no text layer instead of handing you an empty file. The only way to get text out of a scan is optical character recognition, which is what the OCR switch is for.

OCR is a guess, and guesses need proofreading

OCR draws each page, finds shapes that look like letters and outputs its best interpretation. Modern engines are good on clean 300-DPI scans of ordinary print, and much worse on handwriting, faxes, skewed pages, tables, unusual fonts and low-contrast photocopies. Numbers, names, product codes and Arabic diacritics are the usual casualties. Read OCR output before you rely on it: a single wrong digit can change a total or an account number.

OCR here is opt-in and off by default because it is heavy. Turning it on downloads the recognition engine (about 4 MB of WebAssembly) and one language model: roughly 11 MB for English, 1.7 MB for Arabic. Your browser caches both, so it is a one-time cost per language, and recognition then runs entirely on your machine. Nothing is uploaded at any point, and pages that already have a text layer are never sent through OCR — those come out exactly.

What you get, and what the layout switch does

Extraction follows the order in which the PDF stores its content, which is usually reading order but not always: multi-column pages and sidebars can interleave. With Keep layout on, the extractor tries to preserve spacing and line breaks by placing characters roughly where they sit on the page — better for tables, worse for reflowing the text afterwards. With it off you get a cleaner stream of words that pastes neatly into another document, at the cost of columns running together.

Page selection uses 1-based numbers in the form 1-3, 5, 8-12; leave the field empty for the whole document. An encrypted PDF has to be unlocked first, because the engine cannot read page content without the key and reports that instead of returning a partial result. One limitation belongs to every extractor, not just this one: if the PDF's font data carries a broken character mapping, the text comes out as nonsense glyphs. Only OCR can work around that, because it reads the pixels instead of the mapping.

Frequently asked questions

Why does the tool say my PDF has no text layer?

Because its pages are images, which is what a scanner produces. There are no characters stored in the file to copy out, only pixels, so ordinary extraction returns nothing. Turning on OCR makes the browser render each page and recognise the text with a local model — about 11 MB for English and 1.7 MB for Arabic, downloaded once and then cached. Expect to proofread the result.

Do I need OCR for a normal PDF?

No. If the document was exported from a word processor, a design tool or a browser print dialog, it almost certainly has a text layer, and ordinary extraction is exact and fast. OCR is slower, needs language data and introduces recognition errors, so it is worth using only on scans.

How accurate is OCR?

It depends on the scan. Clean, straight, 300-DPI pages of ordinary print come out nearly perfect. Skewed, faded, handwritten or faxed pages produce errors, most often in numbers, names and Arabic diacritics. Treat every OCR result as a draft that needs proofreading; the tool always tells you which pages came from OCR rather than from a real text layer.

Does OCR upload my document?

No. Recognition is designed to run in your browser, and nothing is uploaded at any point. Where an OCR engine is included, the first use of a language downloads that language's recognition data as a normal web asset and caches it, and recognition then runs locally. Your pages and the recognised text never leave your device.

Does the extracted text keep the original layout?

Only approximately. With Keep layout enabled the extractor places characters near where they appear, which preserves tables and columns reasonably well but adds irregular spacing. With it disabled you get a tidier stream of words in the file's content order, and columns can run together.

Can I extract text from a password-protected PDF?

You have to remove the password first. Use the Unlock PDF tool on a file you are allowed to open, then run extraction on the unencrypted copy. Extraction cannot read an encrypted document without the password.
